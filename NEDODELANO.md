# APEXWOLT B2B — что ещё не доделано (оставшаяся работа)

Список незавершённого на момент передачи. Сгруппировано: что нужно от заказчика, техническое, дизайн/UI.

---

## 1. Нужны данные или решения заказчика

1. **Средняя цена на МП** — не решено, как и откуда брать. Проверили 3 магазина заказчика: Ozon (не тот ассортимент), Wildberries (есть только 3 позиции инструмента), Яндекс.Маркет (пусто). Ждём ответ заказчика: какую цену считать «ценой на МП», кто вносит значения. Пока в данных МП = МРЦ (заглушка).
2. **Реальные фото товаров** — сейчас у большинства позиций логотип-заглушка. Нужны настоящие снимки.
3. **Количество в упаковке / единицы измерения** по позициям.
4. **Реальные условия для FAQ** — минимальная сумма заказа, отсрочка платежа, срок гарантии, доставка в регионы. Сейчас в `dist/faq.html` сформулировано как «уточнит менеджер».
5. **Точные связки аксессуаров** для блока «Рекомендуем с этим товаром» на странице заявки — сейчас работает эвристика (по категориям и аккумуляторной платформе), заказчик должен дать точные соответствия.

## 2. Техническое (доделать на проде)

6. **Реальная отправка уведомлений** — письма менеджеру (SMTP), Telegram-бот, рассылки. Сейчас это заглушки: пишут в лог и в локальный JSON (`backend/`). Ключи — только в переменных окружения, не в код.
7. **Реальная база данных** вместо JSON-заглушек (заявки `requests.json`, подписки `subscriptions.json`) — Yandex YDB serverless или Managed PostgreSQL.
8. **Авто-уведомление «о поступлении»** + синхронизация остатков. Сейчас сайт только **собирает подписки**; само письмо «товар появился» и сверка остатков подключаются на проде.
9. **Настоящая авторизация компании + личный кабинет.** Сейчас ЛК — демо. Нужны: вход, персональные цены по индивидуальному коэффициенту, история заказов, документы (счёт, УПД).
10. **Полноценный «повторный заказ»** через историю заказов (сейчас лёгкий вариант: сохраняется только последняя заявка локально на устройстве).
11. **Деплой прода на Yandex Cloud** — Object Storage (bucket) + CDN + TLS-сертификат + Cloud Function для заявки (бэкенд уже написан под это). Разворачивать **в аккаунте заказчика** (его биллинг, его персональные данные). См. `docs/zapros-zakazchiku.md`.
12. **Домен** — заказчик покупает и привязывает.
