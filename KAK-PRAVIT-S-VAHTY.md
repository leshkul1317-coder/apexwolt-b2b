# APEXWOLT B2B — работа с телефона на вахте

## Основные адреса

- Репозиторий: `https://github.com/leshkul1317-coder/apexwolt-b2b`
- Ветка для телефона: `work/apexwolt-phone`
- Код сайта: папка `dist/`
- Основной сайт: `https://apexwolt-b2b-preview.netlify.app`

Работай с телефона только в `work/apexwolt-phone`. Основная ветка `work/apexwolt-ui` может быть связана с Netlify, поэтому промежуточные коммиты в неё не отправляй.

## Первый запуск

1. Открой репозиторий на GitHub и выбери ветку `work/apexwolt-phone`.
2. Нажми **Code → Codespaces → Create codespace**.
3. На телефоне включи горизонтальный режим и при необходимости «Версию для ПК».
4. Дождись открытия VS Code. Превью запускается автоматически.
5. Открой вкладку **PORTS** и ссылку порта `4173`. Порт оставляй **Private**.

Если превью не запустилось:

```bash
bash .devcontainer/start-preview.sh
```

Журнал сервера:

```bash
cat /tmp/apexwolt-preview.log
```

## Порядок работы

Перед правками:

```bash
git status --short
git pull --ff-only github work/apexwolt-phone
```

После одной законченной правки:

```bash
git status --short
git diff --check
git add ПУТЬ-К-КОНКРЕТНОМУ-ФАЙЛУ
git commit -m "Краткое описание правки"
git push github work/apexwolt-phone
```

Не используй `git add -A`: добавляй только конкретные проверенные файлы.

## Промпт для ИИ

> Продолжай APEXWOLT B2B в репозитории `leshkul1317-coder/apexwolt-b2b`, ветка `work/apexwolt-phone`. Сначала полностью прочитай `CLAUDE.md`, `HANDOFF-CLAUDE.md`, `NEDODELANO.md` и покажи `git status --short`. Не переключай ветку, не очищай рабочую копию, не делай reset и не деплой. Выполни только один небольшой согласованный этап. Сохраняй белый premium/minimal, мягкое стекло, синий акцент и локальный Golos Text. После изменений проверь desktop 1440×900 и mobile 390×844, затем покажи diff. Коммит и push делай только после моего подтверждения.

К задаче прикладывай скриншот, название страницы или блока, описание проблемы и ожидаемый результат. Отдельно указывай, разрешено ли менять структуру, текст, анимацию и мобильную версию.

## Быстрые мелкие правки

## Правила безопасности

1. Не деплоить без отдельной команды владельца.
2. Не коммитить токены, пароли, клиентские Excel с себестоимостью и персональные данные.
3. После изменения CSS/JS повышать параметр `?v=` в HTML.
4. После изменения главной проверять скролл-видео на desktop и mobile.
5. Не использовать случайные изображения товаров конкурентов.
6. Не раскрывать персональные цены без авторизации.
7. Не выполнять `reset --hard`, `clean` и массовое удаление.
